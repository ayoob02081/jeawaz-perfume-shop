## Before and after

The original committed middle-page pager exceeded mobile width: 458.06px for
page 500 of 1,000. The first correction removed overflow using a very compact
single row and enlarged controls, including desktop. The requested revision
restores the committed desktop appearance and lets only the center numbers wrap.

- Restore original 40px numeric circles, 8px gaps and padded ellipses. Desktop
  arrows remain their original 20px size. Mobile arrows get 40px hit areas around
  the unchanged 20px icons; numeric targets are 40px as in the original design.
- Below 640px, the nav uses available width and keeps arrows on opposite sides.
  Only its middle section has flex-wrap. The outer nav never wraps its arrows.
- Below 375px, a bounded large-catalog window keeps first/last, current and one neighbor per
  side (up to seven numbers/ellipsis entries). From 375px, show the original
  two-neighbor window (up to nine entries). These are current-page-dependent
  windows, never an array containing every page in a large catalog.
- Ellipses are aria-hidden, noninteractive spans. Existing first/last/current
  and adjacent page links remain useful even for 100+ pages. The original
  out-of-range recovery behavior and single-page hidden pager are preserved.
- One deterministic SSR tree uses CSS visibility at the breakpoint. There are
  no viewport reads, new hooks, effects, request/cache changes or duplicate
  responsive link lists. Compact-only ellipses are merged into the bounded
  desktop window; desktop-visible page destinations remain unchanged.
- ProductsLayout changes only the pager wrapper from fixed h-20 to min-h-20
  with mobile vertical padding. It expands around two rows instead of letting
  the pager spill outside an 80px box. Desktop retains its original 80px height.
- RTL order, Persian labels, aria-current, boundary disabled state, full numeric
  accessible names, bounded long labels, loading guards, real Next Link hrefs,
  replace/scroll behavior and default prefetch policy remain intact.
- productPageHref, URL/filter normalization, sorting, React Query keys, SSR
  snapshot adoption, sitemap and canonical metadata are unchanged. No fetching
  was added. Shared admin/profile pagination and global CSS were not edited.

## Responsive evidence

The center receives 192px at a 320px viewport after 16px page padding, two 40px
arrow areas and two 8px outer gaps. Four 40px entries plus three gaps need 184px;
a seven-entry bounded window therefore fits within two rows. At 375px, the
247px center fits five 40px entries plus four gaps (232px), so the nine-entry
window fits within two rows. Ellipses are narrower; long labels stay bounded.
There is no clipping, line clamp, max-height or hidden third row.
